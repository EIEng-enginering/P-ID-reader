# Rev O — Bounded Batch Imports, Revision Comparison and Project Search

## Delivered code

- `engineering/batch.py`: bounded and recoverable standalone multi-PDF imports (1–250 files), manifest with preflight SHA-256 and bytes, explicit per-item outcomes and retries only for incomplete entries. Multiple source failures never silently count as success. A changed local source is refused on resume.
- `engineering/revisions.py`: deterministic evidence-only extraction comparison using unique `(class, normalised_tag)` keys, without guessing physical asset identity or automatically deciding the latest approved drawing revision. It distinguishes ADDED_ON_DRAWING, REMOVED_FROM_DRAWING, POSITION_CHANGED, INTERPRETATION_CHANGED, SAME_READING and AMBIGUOUS_DUPLICATE_TAG. Untagged/uncertain content is explicitly listed as unmatched. If the source SHA-256 matches, differences are reported as extraction changes rather than a drawing revision.
- `engineering/project.py`: SQLite v9 persistence for immutable batch manifests, per-file outcomes, and immutable, hash-verified revision-comparison snapshots; audit hash chain remains append only. `search_project()` joins source observations and the latest catalogue metadata with actual per-extraction source filename and effective observation review state.
- `engineering/migrations.py`: additive v8→v9 migration; the original v8 database is backed up before upgrading a pre-existing project. The independent Worksheet host SQL and schemas remain unmodified.
- `cli.py`: commands `batch-import`, `batch-resume`, `batch-status`, `compare-revisions`, `revision-comparison`, `project-search`.
- `fixtures/synthetic_rev_o_a.pdf`, `synthetic_rev_o_b.pdf`: generated by `tools/make_rev_o_fixtures.py`, synthetic non-confidential vector drawings; page rendering was visually checked.

## Important boundaries

- This batch feature runs synchronously and locally, not in a hardened subprocess. Malformed PDFs require separate OS-level isolation and resource/time tests before engineering use. Source-preflight hash checks are not equivalent to protection from all filesystem races.
- No folder watcher, remote AI, model retraining, new host workbook integration, automatic line/equipment reconciliation or proprietary database writes.
- A filename/drawing number, tag match, source revision letter or newest import is **not** evidence of the current or as-built facility state. Ambiguous tags never become merged physical assets.
- The Windows PySide6 GUI, independent industrial accuracy benchmark, real Worksheet host gates G4-G7, licensed models and packaged installer remain NOT_RUN / NOT_IMPLEMENTED where indicated in the status register.

## CLI quick start

```powershell
python -m pid_reader.cli batch-import project.sqlite drawing_a.pdf drawing_b.pdf --actor "Engineering reviewer"
python -m pid_reader.cli batch-status project.sqlite <batch_id>
python -m pid_reader.cli batch-resume project.sqlite <batch_id>
python -m pid_reader.cli compare-revisions project.sqlite <before_extraction_id> <after_extraction_id>
python -m pid_reader.cli revision-comparison project.sqlite <comparison_id>
python -m pid_reader.cli project-search project.sqlite --tag P-101 --object-class PUMP
```

`batch-status` includes original paths, hashes and file names: treat it as locally sensitive metadata. Avoid publishing logs for confidential drawings.
